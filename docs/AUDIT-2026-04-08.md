## 1. Critical / High bugs

CH-01 Plaintext passwords + direct string comparison (auth-service)
- Evidence: `services/auth-service/src/main/java/com/sms/auth/service/AdminAuthService.java`, `services/auth-service/src/main/java/com/sms/auth/service/SchoolAuthService.java`.
- Impact: DB leak = immediate takeover; no defense against offline cracking.

CH-02 Seeded admin credentials and committed secrets
- Evidence: hardcoded seeded password in `infra/postgres/init/04-identity-admin.sql`; committed `.env` contains `JWT_SECRET_KEY` and DB creds.
- Impact: predictable credentials; environment compromise risk.

CH-03 Gateway bypass via exposed service ports in `docker-compose.yml`
- Evidence: compose publishes internal services (`8081`, `8082`, `8083`, `8085`, `8086`, `8089`) directly on host.
- Impact: direct calls can bypass gateway JWT parsing/header hardening and any future gateway rate limits.

CH-04 MCP server + Docker socket exposure
- Evidence: `docker-compose.yml` mounts `/var/run/docker.sock` into `mcp-server`; MCP exposes container log endpoints (`services/mcp-server/src/index.js`).
- Impact: high-severity host/container escalation vector if reachable by untrusted users.

CH-05 Multi-tenant scoping inconsistencies can become cross-tenant data exposure
- Fixed on 2026-04-08: standardized `schoolFilter` usage across `school-operations-service`, `finance-service`, and `communication-service` entities that have `school_id` (added missing `@Filter(name="schoolFilter", condition="school_id = :schoolId")` annotations; filter parameter is now a UUID).
- Note: this is defense-in-depth for reads. For full write-safety, APIs should also reject/override any client-supplied `schoolId` that does not match gateway-injected `X-School-ID`.

## 13. Potential Security Threats / Hacking Risks

Highest-risk items first:
1. Trust boundary issues: services rely on gateway; direct service access enables header spoofing risk.
2. Tenant/school authorization gaps: endpoints accept `schoolId` without verifying it matches token claims.
3. Secrets and default credentials in repo/env (`.env`, seeded SQL, compose defaults).
4. Plaintext password storage and direct comparisons (offline cracking risk).
5. MCP server risks (dangerous capabilities, logs endpoints, external calling) and container hardening.
6. MQTT without strong auth/ACLs: topic subscription risk and platform topic exposure potential.
7. Missing rate limits / brute force protection; no MFA.

Mitigations implemented on 2026-04-08 (phase 1):
- Gateway overwrites spoofable identity headers based on JWT, and generates `X-Request-ID` for traceability.
- Gateway rate-limits auth endpoints (HTTP 429) to reduce brute force attacks and reset-code guessing.
- Docker compose binds published service ports to `127.0.0.1` to reduce accidental exposure on developer machines.
